A read of the whole repository at `c97342f` on `main`: the core, the terminal
app, the Linux app, the Apple app, the installer, the release pipeline, the
tools and the docs. Nothing was changed. This is a list of what to work on.

## In short

**Nothing was found that loses or corrupts journal entries on disk.** The
format, the compare-and-swap writes, the migrations, the installer and the
media maintenance all traced as safe. The three test suites pass.

What was found is 112 numbered findings: none critical, 8 high, 52 medium
and 52 low. The high ones are about typed text that is not yet on disk,
about sync, and about what a download proves:

## How to read this

Each finding has an ID, a severity and a confidence.

- **Severity.** *Critical*: loses or corrupts journal text, or exposes it.
  *High*: wrong behaviour a user will hit. *Medium*: an edge-case bug or real
  friction. *Low*: polish.
- **Confidence.** *Confirmed*: the path was traced in the code. *Plausible*:
  believed, but it needs a run or a device to prove. Items marked **checked**
  were read a second time by the reviewer who wrote this report.
- Items that `docs/fix-report.md` already records as open are listed once, in
  section 9, and not repeated as new.

## 1. The core: format, journal and vault

`core/src/journal.rs`, `vault.rs`, `search.rs`, `stats.rs`, `editing.rs`,
`settings.rs`. **No path was found that loses or corrupts an entry.** The
parse and render round-trip, the `(file, index, raw)` relocation, the
compare-and-swap in `edit_file`, day-file deletion and both legacy folds all
traced correctly.

| ID | Sev. | Conf. | Finding |
|---|---|---|---|
| C1 | Medium | Confirmed, checked | **Any root `.md` with a header-shaped line becomes a split journal.** `split_tag_of` (`core/src/journal.rs:472`) treats every root `.md` that is not hidden, reserved or a conflict copy as a legacy split journal, whether or not its name is a split tag. `quire export journal-2026.md` run inside the journal folder, or a `log.md` with timestamped lines, is folded into `split/journal-2026/…` on the next open: the whole journal duplicated as thousands of files. Fix: fold a root file only when its stem is a configured split tag or its entries carry `@stem`; refuse to export into the journal root. |
| C2 | Medium | Confirmed | **Writes follow symlinks, reads do not.** `FsVault::list` (`core/src/vault.rs:163`) uses `DirEntry::file_type`, so a symlinked `journal/` or year folder lists as nothing, while writes go through it. The journal loads empty with no error, and a filed draft disappears from view (it is on disk). Fix: follow directory links that stay inside the root, or refuse them and say so. |
| C3 | Medium | Confirmed | **A legacy fold that fails after copying shows every draft twice, and deleted drafts come back.** `migrate_legacy_inbox` (`journal.rs:1300`) copies into `inbox/` then retires `inbox.md`; if a later step fails (a non-UTF-8 day file, an unwritable `.quire/`), `inbox.md` stays and both are read. Deleting the copy re-inserts it on the next open. Same shape for `<tag>.md`. Fix: hide a legacy entry whose raw text is already in the day tree while the legacy file exists. |
| C4 | Medium | Confirmed, checked | **`import_text` writes one synced file per entry and cannot be retried.** `journal.rs:1263` calls `insert_sorted` per entry: a paste of 1,000 entries is 1,000 fsynced rewrites, and a failure at entry *k* leaves the first *k−1* written, so pasting again duplicates them. Fix: group by day and call `insert_entries(day, raws, true)` once per day, as the migrations do. |
| C5 | Medium | Plausible | **Curly quotes are not phrase quotes in search.** `tokenize` (`core/src/search.rs:117`) knows only `"`. The Apple search field leaves smart quotes on, so `“exact phrase”` typed on an iPhone becomes two terms that never match. Needs one try on a device. Fix: accept `“ ” „ « »` in all three ports and turn smart quotes off on the field. |
| C6 | Low | Confirmed | **A quoted token is still read as an operator.** `"tag:work stuff"` becomes a tag that can never match; `"is:starred"` cannot be searched as text. An invalid `before:March` is silently dropped, so the search returns more than was asked. |
| C7 | Low | Confirmed | **A title ending in ` *` reads back as starred** (`journal.rs:366`). "Rated 5 \*" saved unstarred reloads as "Rated 5", starred. It is the format's own ambiguity, but Quire writes it without warning. |
| C8 | Low | Confirmed | **Path checks are case-sensitive and the vault joins blindly.** `check_entry_rel` (`journal.rs:179`) lets `.Quire/…` and `Assets/x.md` through on a case-insensitive disk, and preamble files through as entry files. `FsVault::path` (`vault.rs:75`) accepts an absolute path or `..`. | C9 | Low | Confirmed | **Relative links outside `assets/` break when an entry moves trees** (`journal.rs:1579`). Only targets resolving into `assets/` are rebased; the `to_rel` parameter is there, unused. |

| C11 | Low | Confirmed | **`.quire/migration/` grows without limit.** While jnl or Nook on another device keeps recreating `inbox.md`, every open adds a copy, which then syncs. |
| C12 | Low | Confirmed | `keep_preamble` (`journal.rs:1012`) uses a substring test: `# Notes` is dropped when `# Notes 2025` is already kept. |

**Improvements**

- **A typed error.** Errors are `String`, and shells match on wording
  (`linux/src/app.js:1087` tests `/changed on disk/`). An enum with a code
  (stale, busy, unreadable, bad input) stops a reworded message breaking the
  stale-save handling.
- **Lenient settings.** A known key with the wrong type fails the whole parse
  and the file is moved aside (`core/src/settings.rs:103`). The terminal and
  desktop apps update separately, so an older one can set aside a newer one's
  settings. Read each known field leniently, falling back to its default.
- **Snapshot size.** `Entry` serialises both `body` and `raw`, so every
  snapshot sends each entry's text twice.
- **Search cost.** `Query::matches` lowercases title and body per entry per
  query, and the bindings re-parse the query on every call
  (`bindings/src/lib.rs:453`). One core `search(entries, query)` fixes both.
- **Load cost.** Each load walks the three trees twice and re-reads every
  root `.md` with no entries.
- **Tests to add.** A symlinked `journal/`; an export saved into the root and
  then a load; a fold failing after the copy; `import_text` failing midway; a
  title ending in ` *`; curly-quote and quoted-operator searches; a hidden
  folder under `journal/`.

## 2. The core: media, backups, imports and maintenance

`core/src/extras.rs`, `media.rs`, `media_cleanup.rs`. **No path was found
that loses an entry or a media file outright.** Every journal rewrite here
goes through `edit_file`; moves are destination-first; the orphan check is
conservative; a transcode replaces an original only when it is smaller and
not empty. ffmpeg and the converters are run with argument lists, never a
shell, and there is no zip code to slip through.

| ID | Sev. | Conf. | Finding |
|---|---|---|---|
| M1 | High | Confirmed, checked | **Data Saver's parked originals are never pruned unless a maintenance action is run by hand.** `prune_media_recovery` is called only from `cleanup_media`, `archive_orphan_media` and `compress_existing` (`core/src/media.rs:1220`, `media_cleanup.rs:253`, `:294`). Someone who attaches video and never opens Maintenance keeps every original for good in `.quire/media-cleanup/`: a 200 MB clip compressed to 30 MB costs 230 MB. The "saved" figure counts the saving anyway, `sizes()` does not count the folder, and because it is inside `.quire/` it syncs to every device and goes into every backup. Fix: prune from `compress_asset` or once on open, show the recovery folder's size beside the saving, and leave it out of scheduled backups. |
| M2 | Medium | Confirmed | **Media cleanup copies every file through memory and needs twice the disk.** `cleanup_media` and `archive_orphan_media` (`media_cleanup.rs:398`, `:257`) read each asset whole, write it twice and read both back. A 1.5 GB video needs about 3 GB of RAM in orphan clearing. If the disk fills at asset *k* the run stops, the copies of 1 to *k−1* stay, and the next run writes `name-2.ext` beside them. Worst on the first cleanup after a Nook migration, where every asset is flat. Fix: use `park_file` (a hard link or rename, already there) and compare by size or streamed hash. |
| M3 | Medium | Confirmed | **The markdown-folder import dates undated notes by creation time, and re-imports duplicates.** `file_date` (`core/src/extras.rs:1405`) prefers `created()`, which on Linux is when the file arrived on that disk, so an unzipped or synced vault is filed on the day it was copied. The dedupe key includes a per-date seconds counter in path order, so adding one file and importing again shifts and duplicates the others. Fix: take the earlier of created and modified; key made-up times on date, title and body. |
| M4 | Medium | Confirmed, checked | **Data Saver drops the colour profile.** Nothing in `media.rs` reads or writes an ICC profile. A Display P3 iPhone photo is re-encoded untagged and shown as sRGB, visibly flatter. Anything over 2048 px, and every JPEG made from a HEIC, goes through this; at attach time no original is kept. Fix: carry `decoder.icc_profile()` into the encoder. |
| M5 | Medium | Plausible | **Media cleanup can overwrite one moved file with another whose name differs only in case** (`media_cleanup.rs:358`). `IMG.jpg` and `img.jpg` from two folders, on a case-insensitive disk: the second write replaces the first. The final check catches it before anything is removed, but the entries have already been relinked to the wrong picture. Needs a test on APFS. |
| M6 | Low | Confirmed | **The backup just made is the one pruned when the clock goes back** (`extras.rs:1035`, `:1115`). Backups sort by a local-time stamp; after the autumn change or a flight west the new one sorts oldest and is deleted, while the run reports success. Fix: never prune the backup just made; use UTC in new names. |
| M7 | Low | Confirmed | **The Linux delete dialog can say a file is unused when it is used.** `Asset.referenced` uses the careful matcher; `Asset.owners` uses exact paths (`extras.rs:208`, `:243`). A file linked through `<img src>` or with different case shows no owners, and `delete_asset` removes it for good. The Apple app parks the same delete for 30 days. |
| M8 | Low | Confirmed | A Day One import that fails partway leaves its copied media orphaned, and a retry copies it again as `-2` (`extras.rs:1600`). |
| M9 | Low | Confirmed | `import_transfer` on plain paragraphs stamps them with the current time, so a retry after a partial failure duplicates them (`extras.rs:1642`). |
| M10 | Low | Plausible | A backup can verify while missing files: the copy loop skips directory entries that error (`extras.rs:872`), and the check compares the copy with what was copied, not with the source. |
| M11 | Low | Confirmed | The Day One import follows symlinks in the export's media folders (`extras.rs:1577`), so a crafted export can pull a private file into `assets/`. |
| M12 | Low | Confirmed | Renaming `@caf` to `@x` turns `@café` into `@xé` (`extras.rs:1773`): the match is not checked for a letter after it. |

**Improvements**

- **Split `extras.rs`** (2,689 lines) into `assets`, `tidy`, `moves`,
  `backup`, `import`, `tags`, `config`, `sidecar` and `time`, each with its
  tests; `sizes` and `stats_extra` belong in `stats.rs`.
- **Duplication.** Three `percent_decode`s, two atomic writers, two tree
  walkers and four link patterns with different grammars.
- **Dead code.** `LinkIndex.all_text` (still built on every Media Library
  open), `is_referenced`, `referenced_assets`, `handled_assets`,
  `content_files`, `human_bytes`.
- **The vault rule.** The Data Saver ledger is a sidecar but is read, written
  and locked with `std::fs` (`media.rs:743`). It needs no real path.
- **One lock across apps.** The backup and restore guard is per process. With
  the desktop and terminal apps both open, a save during a restore's swap
  leaves the journal part-moved.
- **ffmpeg.** No timeout; an audio-only `.mp4` fails `-map 0:v:0` on every
  run and is never marked done; a transcode is accepted if smaller, with no
  duration check.
- **Performance.** `list_assets` reads every markdown file twice, clearing
  orphans three times; `candidates()` folds every file name for every web
  link.
- **Tests to add.** Restore end to end; disk full in cleanup and the retry;
  `merge_conflict` when both sides edited one entry; re-import after adding a
  file; prune order across a clock change; `rename_tags` with a conflict copy
  pending.

**Improvements**

- **Performance on a cloud folder.** `save_draft` reloads the whole journal
  on every autosave (`app.rs:765`); the Apple app stopped doing this. Outside
  the composer the whole tree is walked every 4 seconds on the UI thread.
- **Usability.** Today has no key to open an On this day entry or a listed
  draft (mouse only). Long jobs show no "working" line. The date prompt
  appends only. Search shows titles with no matched text. A refused save says
  "Reloaded — try again", which cannot work from the composer. There is no
  trash for `d`.
- **Colour.** `NO_COLOR` is not honoured. Faint text is about 3.4:1 on the
  light themes and carries file paths and placeholders.
- **Split `app.rs`** (3,167 lines) into `state`, `select`, `composer`,
  `lists`, `settings`, `jobs`, `mouse` and `run`. Settings should be one table
  of rows: today its `_ =>` arms mean row 15 in one place and row 23 in
  another.
- **Tests.** None for `lib.rs`, `cli.rs`, the download path or `update`'s
  arguments. No render test below 80×24: a `TestBackend` sweep of every
  screen from 1×1 to 120×40 would pin the no-panic property.

Known open items re-checked and still as recorded: `^i`; `h`/`k` against
`j`/`l`; arrows in a column filter; Look back's year order; prompts that do

## 7. The same fault in more than one place

These are worth fixing once, in the core, and not three times.

1. **Rows are remembered by position across reloads.** Terminal (T18), Linux
   (L2) and the Apple reader (S2) all act on the wrong entry after the list
   changes underneath. The core already identifies an entry by file and raw
   text; the shells should re-find their selection the same way.
2. **One unreadable file.** The terminal goes stale silently (T2), Apple
   shows no journal (A6), Linux fails its first load and skips the PIN (L7).
   One policy: load what can be read, name what cannot, refuse writes to it.
3. **The whole journal is reloaded and re-sent after every save.** Terminal
   and Linux do it on each autosave (L5); Apple rebuilds from a full JSON
   load; every snapshot carries each entry's text twice. A core call that
   returns only the changed files serves all three.
4. **Faint is used as a text colour** and fails contrast in the light themes
   in every shell. Darken the token in `themes.json`, or add a second token
   for placeholder text.
5. **Delete has no undo anywhere**, and the confirmation differs by shell and
   by gesture (T4, the Linux dialog, the Apple row). The media side already
   has a 30-day recovery folder; entries deserve the same.
6. **Guards are per process.** Backup, restore and cleanup do not stop the
   other app, or a second terminal, from writing during them.
7. **Text is not protected equally.** Drafts are autosaved with a recovery
   copy on iPhone; filed edits on Linux (L1) and everything on the Mac are
   not; the terminal has no save ceiling (T5).
8. **Four files hold a third of the code**: `JournalStore.swift` (4,072),
   `app.rs` (3,167), `app.js` (2,706), `extras.rs` (2,689). Each section
   above says how to split its own.
